## S1-FULL (2026-11-05)

| # | Decision | Meaning |
|---|---|---|
| S1F-1 | **Opt-in cloud (authorized by the S1-FULL brief; overrides the "no cloud" parts of R2 X1/X2/X7 and R3 X1)** | New self-hosted service `cloud/`, sign-in by device Ed25519 key challenge (no password / no email sign-up; account_id = public key fingerprint). Every cloud feature is off by default and turned on one by one; local mode makes zero public-internet requests. Never leaves the machine: screenshots, the Runtime `index.db`, private keys, the Runtime token. Chat only sends context bundles the user has previewed; Meetings only send 30 s audio chunks; weekly-letter email subscriptions coexist with local folder subscriptions (D38); the card server only relays, and clients verify signatures offline. Server logs only contain req_id/method/route/status/ms. See `docs/design/S1-FULL-ARCH.md`. |
| S1F-2 | **Reject small-order / non-canonical Ed25519 public keys** | Measured (Node 24 / OpenSSL): when the public key is the identity point, the signature `R=identity point, S=0` verifies for any message (256/256); all 8 small-order points can forge (success rate about 1/order). `cloud/src/auth.ts` `isWeakPublicKey` returns 400 `invalid_public_key` at the challenge step; test `cloud/test/auth.test.ts`. |
| S1F-3 | **`cloud/` may use `nodemailer` 10.2.1 (pinned exactly, no transitive dependencies)** | Hand-written SMTP (STARTTLS / AUTH / dot-stuffing / header injection / MIME UTF-8) is riskier than pulling in the standard library; only in `cloud/`, no new dependency on the Electron side. |
| S1F-4 | **`smtp` mode must configure `CLOUD_EMAIL_PEPPER`** | After unsubscribe only `HMAC(pepper, email)` is kept; if the pepper lives in the same DB, a DB leak lets the emails be brute-forced back. dev (outbox / off) mode still allows a DB-generated pepper. |
| S1F-5 | **C11 (adding "shared moments" to the weekly letter) is deferred to Phase 4, together with C18** | The shared-moments object from C18 does not exist yet; doing it early would degrade into literal overlap, which violates the brief. |
| S1F-6 | **Microphone is used only for opt-in meetings (overrides PRIV-10 "no microphone")** | Single entry point `components/meetings/recorder.ts` (`getUserMedia({audio:true, video:false})`). Main-process mic gate: only `media` + audio only + app document only + consent given (checkbox + native confirm) + recording in progress (3 h TTL); everything else is refused. `package.json` has only one `NSMicrophoneUsageDescription`, Lens's own; after-pack no longer removes it, but still removes camera / system audio capture / Bluetooth. Guard tests now check "only the recorder can touch the microphone" instead of removal: `tests/privacy/no-mic.test.ts`, `tests/capture/og02-capture.test.ts`, `tests/shell/og-round-2026-11-05.test.ts`. |
| S1F-7 | **Shared moment = an object signed by both sides, never inferred** | One side proposes and signs; the other accepts by signing the sha256 of the canonical JSON; the server only relays, and clients verify both signatures offline on every read; if either side deletes it, it disappears for both; `visibility:"letters"` is covered by both signatures, and only it can go into the weekly letter. D31 literal overlap is downgraded to "Keyword overlap (Unverified, not shared moments)" and no longer goes into any letter. Third-party accept/decline returns 404 (does not reveal existence). |
| S1F-8 | **The source of cloud Workflow extraction is written as `provenance.extraction.source = "cloud_extracted"`** | No new ProvenanceKind: the Library would file a new kind under "Observed", which would misrepresent the source. When sharing a `.lensskill`, `cited_items` / `session` are stripped. Upstream `behavior_patterns().skills` is currently empty (2026-11-06), so real steps only come from cloud extraction. |
| S1F-9 | **Performance (C16) does B + C only, not A** | Counts = the same rows you see when you click in; a source that is not connected shows "Unknown / not connected" instead of 0; `transcript_commit` is a `git commit` call in a transcript and does not guarantee a commit was made. Projects only show activity: no completion percentage, no date prediction. Visible on this Mac only. |
| S1F-10 | **Proactive layer (C17) is all off by default and stays silent when context is insufficient** | Event triggers: a meeting transcript finishes; a shared moment **I proposed** is accepted by the other person (published when first seen in sync, not when I accept someone else's). Every decision (trigger/silent + reason) is written to a local log; notifications carry no body by default. |
| S1F-11 | **Backups restore Workflows by original id, only for "manifests signed by my own identity" (C21 revision, lead decision)** | On export the manifest (including each file's sha256) is signed with the Lens identity key: `persome-lens-backup-v1\n` + canonical JSON, stored as `manifest.sig.json` (the second entry inside the encrypted bundle). On restore `evaluateTrust` → `mine` (current identity or `previousIdentities()`) / `foreign` / `unsigned` / `invalid`. `mine` → restore every version byte for byte by original id (newer local versions are not overwritten; forks are saved as `imp-*` copies, and ids the Runtime is currently observing whose v1 differs are also saved as copies); `foreign` / `unsigned` → still go through D36 / S1-R3-SEC L4 (renumbered copies, with full history); a signature that is present but fails verification → the whole bundle is refused and nothing is written. Encryption does not imply authorship. **Consequence**: private keys are not in the backup, so restoring on a new computer (new identity) only yields copies. See `s1full-log/C20-C21.md` §3 / §6, DEVIATIONS D84. |
| S1F-12 | **IMAP connector: read-only, implicit TLS (993) only, app-specific passwords only; OAuth connectors BLOCKED (C19)** | No STARTTLS / 143 / plaintext; `rejectUnauthorized: true`, TLS ≥ 1.2, SNI; only 7 read-only commands are sent (EXAMINE, not SELECT); credentials are encrypted with a safeStorage SecretBox, and saving is refused when it is unavailable; separate consent is required first, and revoking deletes the credentials. This is Lens's first outbound connection to a non-loopback address (a host the user enters); the code is confined to `src/main/connectors/imap/**`, with static tests. Google / Notion / Outlook and other OAuth connectors have no client id, so BLOCKED. See `s1full-log/C19.md`, DEVIATIONS D80–D82. |
| S1F-13 | **Tool-call summaries are on by default on import (C20)** | Overrides S1-R3-06 "off by default": keeps tool names, the first line of commands, and paths of written / edited files (the home directory written as `~`, Runtime / Lens data directory paths removed, tokens / emails masked); tool output is never imported; can be turned off per import. Cost: whatever redaction misses is now imported by default. See `s1full-log/C20-C21.md`, DEVIATIONS D83. |
| S1F-14 | **X3 (HET transport) is still not approved** | HET is still `disabledTransport`, 0 minutes, "Not measured"; `src/main/het` and `src/main/cloud` do not import each other (`tests/het/c23-transport.test.ts`). Approval needs the user to answer 5 things: budget and behavior when exhausted; provider / model (pinned per anchor version, temperature 0); scope of text leaving the machine and the provider's retention terms (per-item preview recommended); whether to reuse the cloud `/v1/chat/completions` with `task:"het_assess"`; minutes shown as "Estimate" + anchor version, not treated as a score. See `s1full-log/C23.md` Task 2. |
